# Formal Methods Directory

This document is the navigation authority for the formal artifact. It answers four questions: what formal work exists, what each part tries to establish, where its source is located, and how a reviewer selects it with `verification/run_proofs.py`.

Each result means exactly what it says. A proof establishes its theorem under its assumptions. A
model check explores its configured state space. A control shows that its named defect is detected.
Verus proves the written Rust contract, and executable checks compare selected inputs with expected
outputs.

The construction registry binds 36 obligation schemas to 69 clause occurrences, separating primary
responsibilities, contributing clauses, supporting facts, derived results, selected policies, and
alternative modes. The local proofs remain evidence for their written formulas. The selected
Budget/Sequential instance below binds two schemas to exact catalog semantics; other selections need
their own bindings before they receive that credit.

Interpretation is a separate check. Supplied owner, controller, timing, or assurance labels do not
establish real authority. A counterexample changes the theory only when the model contains the
intended obligation, all decisive behavior, the independent authority boundary, the claimant
perspective, and the relevant failure model.

[Claim-Relative Ownership and Assurance](claim-relative-ownership.md) defines the approved
cross-abstraction vocabulary. Its first formal package types claim frames, property-specific
coverage, one canonical owner or no owner, matching technical accountability, claim-specific TCBs,
delegation, transfer, owner-issued guarantees, claimant assurance, and related abstraction frames.
That package does not establish catalog instantiation, an ALK authority certificate, or
implementation or deployment conformance.

## Reviewer entry points

| Need | Container command |
|---|---|
| See every primary work item | `run_proofs.py list` |
| Find one structure or subject | `run_proofs.py show Budget` |
| Inspect a selection without executing it | `run_proofs.py run --subject Budget --dry-run` |
| Run a focused selection | `run_proofs.py run --subject Budget` |
| Run one research area | `run_proofs.py run --area execution` |
| Run only TLAPS modules | `run_proofs.py run --engine tlaps --area construction` |
| Run controls and their isolated baselines | `run_proofs.py run --controls-only --area structures` |
| Audit the complete ALK-SPEC boundary | `run_proofs.py run --subject ALK-SPEC-1 --repeat 2 --json /out/alk-spec.json` |
| Reproduce a two-pass result set | `run_proofs.py run --all --repeat 2 --json /out/results.json` |

`run` requires either an explicit selector or `--all`. Read-only discovery works from a checkout. Proof execution is refused outside the pinned container.
